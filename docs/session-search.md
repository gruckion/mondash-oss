# Sessions search and draft work

Sessions covers activity in the last seven days, not the entire chat history. The default Archive status filter is **Not archived**. Choose Archived, or Show all, in Sort and filter to include archives. Existing device preferences acquire this default while preserving the chosen tool, sort and display options; an explicit Show all choice persists. Reset restores Not archived.

Most recent groups sessions by their latest activity in the viewer's local timezone: Today, Yesterday, weekday names back to Monday, Last week, Earlier this month, Last month, older month names in the current year, then older years. Empty headings are hidden, and calendar labels update while the app is open. The seven-day source window is unchanged, so older headings appear only when older sessions are available. Search results keep relevance ordering, and Oldest first / Title retain their chosen order without date headings.

Codex sessions are discovered through recent date folders, the archive folder and the read-only local `state_5.sqlite` index. The index supplies current archive flags and finds old threads resumed this week. Claude archive flags come from Claude Desktop’s `claude-code-sessions/<account>/<organisation>/local_*.json` records, matched to current and prior CLI IDs. Exact current IDs take priority over historical aliases. Records are read in bounded batches. Remote Control disconnection (4090) is **not** evidence of archiving. Missing provider records leave the state unknown and the session visible. No Mondash archive state is stored.

Sessions supports right-swipe Archive/Unarchive for Codex, with the same 72-point threshold and haptics as Inbox. iOS context menus and web buttons also expose the action. The backend calls the installed Codex app-server’s native `thread/archive` or `thread/unarchive`, verifies the flag in Codex’s own DB, then rebuilds the Sessions snapshot. Rows remain visible on a failure. Claude Desktop has no supported external archive command in the installed app/CLI; Claude swipes are disabled, and its archive state is read only. Cloud-only Claude archive state is not available from Desktop metadata.

On iOS 26+, Sessions is a native search-role tab using Expo Router's `Stack.SearchBar` with automatic placement. UIKit integrates the field into the tab bar and moves it above the keyboard while editing. Shared query state survives keyboard dismissal and tab changes; Cancel clears it. Older iOS and Android use the input above the list; mobile web uses its bottom bar, and desktop web uses the input above the list. Issues/Scoping keep their segmented tab-bar accessory.

After a 600 ms pause, the app sends the query and every session surviving the archive/tool filters: ID, tool, title, subtitle and the displayed preview (up to 1,200 characters). Hiding previews in Display also removes them from the request. No transcript, prompt, local folder, branch, credential or hidden archive is sent. The API validates the payload and keeps the TypeSafe key on the Mac.

Jev answers independent Score questions in batches of 50, with up to three batches running at once. The client timeout allows successive waves for longer lists. The ordered relevance levels range from unrelated to a direct match. Code normalizes each score to 0–1, sorts globally by relevance, and uses recency for ties. Scores are relevance ratings, not probabilities. All candidates remain available; there is no relevance cutoff that could hide the session being sought. Without a query the saved sort applies. While a query settles, or Jev fails, text matches come first. Superseded searches are cancelled and answers are keyed to the exact query and visible content, cached for ten minutes. A response to an older query cannot reorder the current results.

Issues has Now, Other and Drafts pages. Drafts uses the same rich PR cards as Other, with checks, change counts, conflict information, review replies and linked agent sessions. All fetched owned drafts appear, including drafts attached to a ticket. Ticket cards keep their draft PR links too. Drafts has no standalone PR age cutoff. Now excludes the separate draft group and Other keeps backlog and non-draft standalone PRs.

Validation: exercise archive/unarchive metadata, persisted filter migration/reset, rich draft presentation and the search API contract; check a representative query against Jev; run `bun run check`, build the web and signed iOS Release apps, restart the backend, then install the signed build on a paired iPhone. The native keyboard/tab-bar search arrangement requires a device check in addition to web verification.

Owned PRs and their refresh probe are paginated so older drafts stay visible. Search candidates use a stable tool/ID order; rankings cache completed responses for ten minutes, and obsolete requests can be cancelled.

Each Jev question includes its selected candidate explicitly. In the real ACH search, referring only to an array index confused candidate selection; explicit question context put the original ACH session first. The backend disables [Bun’s default ten-second idle timeout](https://bun.com/docs/runtime/http/server#idletimeout), so a valid batch search can finish within the provider and client deadlines.
